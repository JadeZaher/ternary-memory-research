Trits, Routes, and Fixed Points

What this research track is, what the hardening pass actually found, and where it goes next. Read it in plain words or in full notation; every symbol used in the formal mode is defined in the glossary at the end.

Reading mode
Same content, two treatments. Tables and the glossary show in both.

1. The one-sentence version

We are testing whether a neural network can be built from weights that take only three values, minus one, zero, and plus one, and still (a) speak passable English, (b) solve small logic puzzles by "thinking in loops", and (c) learn to skip the parts of itself it does not need for a given input. The three-value idea is what makes the network small enough to sit in a chip's fast memory; the skipping and looping ideas are what would make it cheap to run there.

Three claims are under test. (1) A transformer whose linear maps use weights in {−1, 0, +1} with one shared scale per 256-weight block can be trained from scratch with a straight-through estimator and stay close to an FP32 twin. (2) A weight-tied recurrent denoiser trained by fixed-point forcing converges toward a per-cell fixed point on constraint-satisfaction problems, so the contraction ‖s⁽ᵏ⁺¹⁾ − s⁽ᵏ⁾‖∞ < εexit is a usable stopping rule. (3) A per-layer three-way router (execute / route around / exit) trained with Gumbel-softmax learns to skip layers in a way that beats a random router at the same skip rate.

2. Three ideas, each in both voices

2.1 Ternary weights

plain words

A normal network stores each connection strength as a 32-bit number, roughly a dial with four billion positions. Here each connection is only a switch with three positions: pull negative, do nothing, pull positive. To keep the network from losing all sense of scale, every block of 256 switches shares one ordinary number that says "how strong is a pull in this block". Three positions need about 1.6 bits to store instead of 32, so the network shrinks about twenty-fold.

Training a three-position switch is awkward because you cannot nudge it a little. The trick is to keep a hidden 32-bit dial behind each switch during training, nudge the dial, and snap the switch to whichever of the three positions the dial is closest to. At the end the dials are thrown away and only the switches ship. About a quarter of the switches end up in the "do nothing" position, which is why "zero-skipping hardware" is interesting: those connections cost nothing if the chip knows to skip them.

full notation

Let W ∈ ℝ^{m×n} be a master weight matrix, partitioned into blocks of g = 256 consecutive entries. For each block b:

γ_b = mean_{ij ∈ b} |W_ij| (block scale, γ_b > 0) W̃_ij = clip( round( W_ij / γ_b ), −1, +1 ) ∈ {−1, 0, +1} y = W_eff x + bias, W_eff = W̃ ⊙ γ (γ broadcast per block)

The straight-through estimator defines the backward pass as ∂L/∂W := ∂L/∂W̃, i.e. the rounding is treated as the identity for gradients. Implementation: W_ste = W/γ + (W̃ − W/γ).detach(). Storage cost is log₂ 3 ≈ 1.585 bits per weight, or 1.6875 bits with a 16-bit scale per 256 weights (the TQ1_0 layout). At Kaiming-uniform initialisation, |W_ij|/γ_b < ½ for about 25% of entries, which is the measured zero fraction (0.249 to 0.250 across all seven projection shapes).

The additive form of the product, y_i = γ (Σ_{j∈P_i} x_j − Σ_{j∈N_i} x_j) with P_i = {j : W̃_ij = +1} and N_i = {j : W̃_ij = −1}, contains no multiplications by weights. It models hardware that can skip zeros; on a GPU it executes as two dense matrix products and is measured slower than one (section 3).

2.2 The tri-state router

plain words

A transformer is a stack of layers, and every token normally passes through all of them. The router is a tiny gatekeeper in front of each layer that looks at the token's current state and picks one of three: run this layer, skip this layer and carry on, or stop here and answer now. Skipping is the novel option: earlier work only allowed stopping, which means a token could never skip a middle layer and still use a later one.

The gatekeeper is trained by letting it flip a weighted coin during training and rewarding it slightly for choosing "skip". The honest question is not "does it skip" but "does it skip better than a coin flip at the same rate". That comparison was missing before this pass and is now built into every ledger.

full notation

At layer l with hidden state h_l ∈ ℝ^{B×n×d}, the probe reads the last position and emits three logits:

z = W_r h_l[:, −1, :] + b_r ∈ ℝ^{B×3}, p = softmax(z) a = argmax(z) at inference (per sample) g = gumbel_softmax(z, τ, hard=True) in training (one-hot, straight-through) h_{l+1} = g₀ · f_l(h_l) + (g₁ + g₂) · h_l

Action 0 executes the layer function f_l; actions 1 (route around) and 2 (early exit) both leave h_l unchanged at this layer, and at inference action 2 additionally halts the remaining layers. The auxiliary loss L_route = λ · mean_l p_{l,0} pushes probability mass away from EXECUTE. Two controls accompany every routed model: the same weights with every layer forced to execute, and a random policy per layer with the same measured action frequencies (p̂_{l,0}, p̂_{l,1}, p̂_{l,2}) counted over samples still active at layer l.

Two defects fixed in this pass: the blend previously used g₀ f_l(h) + g₁ h, so a sampled exit multiplied the state by zero; and inference used argmax(z[0]) for the whole batch, so samples 1..B−1 followed sample 0's decision. Physical layer skipping remains a batch-size-1 property; batched evaluation selects per sample without saving compute.

2.3 Recurrent flow reasoning and the fixed-point exit

plain words

For puzzles like Sudoku, the network does not answer in one pass. It keeps a "current belief" for every cell, a list of how likely each digit is, and runs the same network again and again, each time feeding its own beliefs back in and sharpening them. Because the same weights are reused each loop, they are loaded into fast memory once and stay there.

When the beliefs stop changing between loops, the network is done: that is the fixed point. The stopping rule is simply "the biggest change to any belief was smaller than a threshold". Easy puzzles settle in two or three loops, hard ones use the full budget, so compute follows difficulty.

The training recipe matters. The network is trained on beliefs produced by its own loops, not on perfect inputs, so that the loops it sees at test time look like the loops it saw in training. This pass found that the training inputs also accidentally contained the answer, and that the shipped test-time inputs did not. That mismatch is now closed, and the corrected numbers are in section 3.

full notation

A puzzle has n cells and V classes. The condition c ∈ {0,1}^{n×V} is one-hot on clue cells and zero elsewhere, with clue mask m ∈ {0,1}^{n}. The carry s⁽ᵏ⁾ ∈ (Δ^{V−1})^{n} holds a probability vector per cell. With flow time t ∈ [0,1] and noise ε ~ 𝒩(0, I):

x_t = (1 − t) ε + t · c (interpolant; leak-free form) s⁽⁰⁾ = uniform, then clues pinned: s ← (1−m) s + m c s⁽ᵏ⁺¹⁾ = softmax( D_θ(x_t, c, s⁽ᵏ⁾, t) ), clues pinned again Δ⁽ᵏ⁾ = ‖ (1−m) ⊙ (s⁽ᵏ⁺¹⁾ − s⁽ᵏ⁾) ‖_∞ stop when Δ⁽ᵏ⁾ < ε_exit; ŷ_i = argmax_v s⁽ᵏ⁾_{i,v}

Fixed-point forcing: sample k ~ U{0,…,K}, run k steps of the recurrence without gradient to obtain s_FPF, then take one supervised step minimising CE(D_θ(x_t, c, stopgrad(s_FPF), t), y) against the ground-truth assignment y ∈ {1..V}^{n}. If training makes the map contractive around y, ‖D_θ(s) − y‖ ≤ ρ ‖s − y‖ with ρ < 1, then Banach's theorem makes the consecutive-difference test a sound stopping rule; ρ is not measured directly here, only the empirical exit behaviour.

The leak: the original interpolant was x_t = (1−t)ε + t · x₁ with x₁ the full solution, while inference supplies x_t = 0.2 ε + 0.8 c. Probe on the FP32 4×4 model: 75.6% solved as shipped, 100% with the training-style input, 90% with x_t = 0. Training now uses c in the interpolant so both regimes coincide.

2.4 FlowRoute: two axes of skipping

Put the router inside the looping network and you can skip along two axes at once: fewer loops (stop early) and fewer layers per loop (route around). The saving multiplies. The catch, which the old ledger missed, is that skipping is only worth reporting next to the solve rate: a network that skips 40% of its work and solves nothing has saved nothing.

Total layer evaluations for one puzzle are E = Σ_{k=1}^{K_eff} Σ_{l=1}^{L} 𝟙[a_{k,l} = EXECUTE], and the reported saving is 1 − E / (K_max · L). Modes compared: all layers, fixed K; step exit only (layers forced to execute); layer routing only; both; and a random-bypass control at the matched bypass rate. A router-free twin trained identically is the accuracy reference.
