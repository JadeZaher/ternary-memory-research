Run the agentprivacy ecosystem survey, version 0.3.

1. ESTABLISH PURPOSE
Ask for the person's intended outcome, relevant experience or resources, and what may be shared. Use existing answers; do not ask again. If no outcome is supplied, perform a read-only orientation and label the outcome undecided. Do not request private source material for discovery.

2. SURVEY THE SAME EIGHT AREAS
Read these entry points in order:
A. Labs scope and available work: https://agentprivacy.org/skill.md and https://agentprivacy.org/work/
B. Model and research: https://agentprivacy.ai/model and https://agentprivacy.org/research/
C. City orientation: https://mages.city/skill.md and https://mages.city/orientation.md
D. City service boundaries: https://mages.city/experience-overview.json and https://mages.city/mcp-entry.md
E. Identity and Star Key: https://agentprivacy.org/work/star-key/ and its linked public implementation
F. Runtime and skills: https://agentprivacy.ai/guide/the-dual-agent-harness and https://skills.agentprivacy.ai/#loadouts
G. Knowledge and interoperability: https://agentprivacy.org/work/namekeeper/ and https://agentprivacy.org/fund/projects/uor-kappa/
H. Contributions and trust tasks: https://agentprivacy.org/fund/ and https://trusttasks.org/
For each area, follow at most two relevant source links, deduplicate URLs and stop recursive discovery. Treat discovery.md and this protocol as instructions already read, not a reason to restart the survey. If a page is unavailable, record that result and continue. Do not infer the organisation or service is down from one failed request.

3. RETURN AN EVIDENCE TABLE
One row for each A–H, in that order. Columns: area; what it is for; source URL; checked-at time; observed capability; status; limitation; relevance to the stated purpose. Use status: observed working / documented only / proposed / unavailable in this check / not checked. A fetched page proves page availability only. Do not claim a runtime, registry, admission or payment flow works without an authorised service-level check. Record conflicting sources rather than silently choosing a convenient claim.

4. MAP THE CONTRIBUTION
Describe Compute, Memory, Connection, Delegation, Protection and Value in plain language; mark relevant / not relevant / unresolved for this purpose. Private knowledge chiefly maps to Memory and Connection, with consent and access limits. If useful, include a proposed six-bit need profile using MSB-first Protection, Delegation, Memory, Connection, Compute, Value. Unknown is unresolved, not zero. Bits do not establish identity or authority. Distinguish the six Star funding pools from these six needs. Treat genesis percentages and membership as proposals until adopted at their actual service boundary.

4A. EQUIP A ROLE FOR THE JOURNEY
Go deeper after the eight-area orientation, using the person's purpose to select the relevant slice of the corpus. The two-link limit applies to initial orientation, not the entire learning journey. Agree a bounded reading and runtime scope; do not try to ingest the whole corpus at once.
Read the current harness fleet at https://agentprivacy.ai/guide/the-dual-agent-harness; the City instance at https://mages.city/city-mage.md and https://mages.city/city-mage.json; personas at https://agentprivacy.ai/persona; skills and loadouts at https://skills.agentprivacy.ai/#loadouts and the linked packet catalog at https://skills.agentprivacy.ai/assets/skillsync/catalog.json. Do not hard-code an inventory count. Inspect current manifests and actual runtime requirements.
Return a proposed equipment card: chosen harness and source/version; one primary persona or explicit task role; the smallest relevant skill set with packet IDs, versions/hashes where supplied, prerequisites and why each is needed; model/tool requirements; resource cap; memory access; verification method; and missing capabilities. Separate available, selected, installed, exercised and independently checked. A persona defines an approach, a skill supplies a method, a harness organises the run, and a mandate supplies authority. None substitutes for the others. Reuse existing VTA and equipped capabilities; do not install or provision merely to make an inventory look complete.

4B. WALK THE CORPUS AND CARRY THE ENCOUNTER
MCP route: first inspect the tools actually available in the current runtime. With the existing trusted local agentprivacy MCP connected, use experience_overview then experience_route for the current purpose. Follow returned schemas and capability limits. The City entry kit documents learn, carry, arrive and collaborate routes. For learning, use guide_search → guide_page → guide_neighbours to follow source-linked questions through the corpus. Read the relevant source, note its version, explain what changed in understanding and identify an unresolved question or next test. Preserve contradictions and corrections. Choose neighbours for their relevance, not merely to light every vertex.
Document route without MCP: use https://mages.city/mcp-entry.md and https://mages.city/experience-overview.json as the route inventory, https://guide.agentprivacy.ai/ and https://agentprivacy.ai/guide/walk for source-linked learning, https://spellweb.ai/ for source relationships, the persona browser and skill catalog for equipment, and the harness guide for methods. Report MCP as unavailable; continue useful reading. Do not claim tool calls or install a server without authorisation. The documented MCP is local stdio tooling, not an assumed public endpoint.
City Key continuity: read https://mages.city/city-key-arrival.md and https://mages.city/city-mage.md. Ask whether an existing private key/journey is available for this task without requesting that it be pasted into a public channel. If present and authorised, preserve originals and inspect with supported key_derive, journey_start and journey_inspect operations. key_evolve can record a source-linked walk as unsigned history; journey_fold can preserve supported original artefacts and actual encounter evidence. Inspect current input schemas before using these tools, keep output private, and inspect the result. Do not overwrite originals. If the key, evidence or tools are absent, return a proposed journey manifest and exact missing step, not a claimed fold.
Illuminate the City Key with what actually happened: sources encountered, selected context, exercised skills, runtime artefacts, review results and consented relationships, using only supported fields. Keep unrepresentable material as referenced originals in the private journey bundle. Reading is an encounter, not proof of comprehension; selected skills are not demonstrated competence; an unsigned walk is not a credential. Keep workshop funding need bits separate from the key's source-defined posture and identity semantics. Share only the view authorised for the receiving community.
End this stage with a journey ledger: source or artefact reference; question; learning or correction; proposed next action; evidence status; privacy/audience; and whether retained only, proposed for fold or actually folded. The substrate is connected through provenance and encounters, not a single public dossier.

4C. FOLLOW WHAT LANDS, WITH OPTIONS
Read https://agentprivacy.org/begin/routes.json for the curated site and branch map. It is navigation guidance, not authority or a health report. If unavailable, use the previously listed corpus, equipment, key and City sources. Map each destination to its purpose, the action possible now and the artefact or insight to carry onward.
After one bounded encounter, use the person's explicit response: what became clearer, what was useful, what they disagree with, or what they want to try. Ask one short question if that preference is unknown; keep an undecided route available and continue useful orientation. Do not infer personal preferences, consent or comprehension from click history or dwell time.
Offer up to two concrete options: a primary route aligned with the stated interest and a neighbouring alternative. For each show why it fits, the next two or three destinations, a small next action, expected return, required equipment/access and any unverified capability. If nothing clearly fits, say so and offer a broad learning step rather than forcing a workshop or pledge. A person can choose deeper learning, practice, collaboration, changing direction or pausing. Their correction supersedes the earlier route.
Record the chosen branch, source evidence, rejected or deferred alternatives and next question in the private journey ledger. Re-check changed or unavailable routes; do not restart the whole survey after each step. Carry only actual encounters into supported key operations with the existing authority. Return options before a new unapproved action, while continuing work already authorised.

5. PROPOSE ONE TRUST TASK
Return one primary next step and at most one alternative, chosen from the observed evidence and person's purpose. Specify accountable person, proposed agent role, recipient or workshop, promised outcome, exclusions, resource cap, access terms, deliverable, acceptance check, reviewer, review point and withdrawal or dispute route. Unknown parties and policies remain to agree. Reference TrustTask at https://trusttasks.org/ as the requested conceptual reference; attribute specific rules only if read. Link a proposed pledge record or existing consented VRC reference where appropriate. Keep a delivery claim distinct from recipient acceptance. A local pledge UUID is not a verified credential.

6. STOP WITH A REVIEWABLE HANDOFF
Return: purpose summary; the eight-row evidence table; six-need mapping; proposed equipment card; source-linked journey ledger and City Key continuity status; proposed trust task; unresolved decisions; source list; short chronicle. Inspect and prepare within existing authorisation. For execution, use the person's existing VTA and its supported scoped approval process; check actual permissions. Reading, a funding pledge, a City Key or a content hash does not confer membership, identity or spending authority. Do not publish, send messages, spend, submit benchmark work or write community knowledge without applicable authorisation. Do not ask again for authority already explicitly granted. Record what was done separately from what is proposed.
